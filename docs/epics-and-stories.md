- Epic: Task Data Model Enhancements
	- Story: Add optional due date field to tasks
		- Acceptance Criteria
			- A task can be created without a due date.
			- A task can store a due date when provided in `YYYY-MM-DD` format.
		- Technical Requirements
			- Continue using the existing `due_date` field across the backend SQLite schema, REST payloads, and frontend task objects.
			- Preserve the current due date input in `packages/frontend/src/TaskForm.js` and due date rendering in `packages/frontend/src/TaskList.js`.
	- Story: Add priority field with P1 P2 and P3 values
		- Acceptance Criteria
			- A task supports only `P1`, `P2`, or `P3` as valid priority values.
			- Any value outside `P1`, `P2`, or `P3` is not treated as a valid priority.
		- Technical Requirements
			- Add a `priority` column to the `tasks` table in `packages/backend/src/app.js` and include it in create, update, and read operations.
			- Extend `POST /api/tasks` and `PUT /api/tasks/:id` validation to accept only `P1`, `P2`, or `P3`.
			- Add priority form state and a priority input control in `packages/frontend/src/TaskForm.js`.
			- Render task priority in `packages/frontend/src/TaskList.js` so the selected value is visible in the list.
	- Story: Default task priority to P3
		- Acceptance Criteria
			- New tasks default to `P3` when no priority is provided.
		- Technical Requirements
			- Apply the default priority in backend task creation so persisted records always have a valid priority.
			- Initialize the create-task form state to `P3` in `packages/frontend/src/TaskForm.js`.
	- Story: Require title for task creation
		- Acceptance Criteria
			- A task cannot be created without a title.
		- Technical Requirements
			- Keep client-side title validation in `packages/frontend/src/TaskForm.js` before calling `onSave`.
			- Keep server-side title validation in `POST /api/tasks` and `PUT /api/tasks/:id` in `packages/backend/src/app.js`.
	- Story: Ignore invalid due date values
		- Acceptance Criteria
			- An invalid due date value is ignored rather than stored.
			- When an invalid due date is ignored, the task is treated as having no due date.
		- Technical Requirements
			- Add backend validation to normalize invalid `due_date` values to `null` before insert and update.
			- Keep the existing edit-mode date normalization in `packages/frontend/src/TaskForm.js` aligned to the `YYYY-MM-DD` contract.
- Epic: Task Filtering Experience
	- Story: Add All tasks filter
		- Acceptance Criteria
			- Users can switch to an `All` filter view.
			- The `All` filter shows all tasks regardless of due date.
		- Technical Requirements
			- Add active filter state to the frontend task view and default it to `All`.
			- Keep the `All` view backed by the full `/api/tasks` response returned to `packages/frontend/src/TaskList.js`.
	- Story: Add Today tasks filter
		- Acceptance Criteria
			- Users can switch to a `Today` filter view.
			- The `Today` filter shows tasks with a due date matching the current date.
		- Technical Requirements
			- Add a `Today` filter control in the frontend task list UI.
			- Compare dates using the existing `YYYY-MM-DD` string contract to avoid timezone drift in `packages/frontend/src/TaskList.js`.
	- Story: Add Overdue tasks filter
		- Acceptance Criteria
			- Users can switch to an `Overdue` filter view.
			- The `Overdue` filter shows tasks with due dates earlier than the current date.
		- Technical Requirements
			- Add an `Overdue` filter control in the frontend task list UI.
			- Determine overdue status from incomplete tasks whose `due_date` is earlier than the current local date.
- Epic: Local-Only Task Storage
	- Story: Keep task data stored locally
		- Acceptance Criteria
			- Task data is stored locally in the application.
			- No external storage dependency is required to use the app.
		- Technical Requirements
			- Continue using the existing local Express API and in-memory SQLite database defined in `packages/backend/src/app.js`.
			- Do not add any external database, hosted API, or third-party persistence dependency.
	- Story: Preserve frontend-only task management flow
		- Acceptance Criteria
			- The feature works without introducing backend changes.
		- Technical Requirements
			- Keep the current interaction pattern centered on `packages/frontend/src/App.js`, `packages/frontend/src/TaskForm.js`, and `packages/frontend/src/TaskList.js`.
			- Reuse the existing `/api/tasks` REST endpoints instead of introducing a new client-side data layer.
- Epic: Overdue Task Visibility
	- Story: Highlight overdue tasks visually
		- Acceptance Criteria
			- Tasks identified as overdue are visually differentiated from non-overdue tasks.
		- Technical Requirements
			- Extend the existing conditional MUI styling in `packages/frontend/src/TaskList.js` to apply a distinct overdue visual state.
			- Base overdue highlighting on the same overdue calculation used by filter and sorting logic.
- Epic: Task Sorting Improvements
	- Story: Sort overdue tasks before other tasks
		- Acceptance Criteria
			- Overdue tasks appear before non-overdue tasks in the sorted list.
		- Technical Requirements
			- Update the ordering used by `GET /api/tasks` in `packages/backend/src/app.js` so overdue tasks sort before other tasks.
	- Story: Sort tasks by priority from P1 to P3
		- Acceptance Criteria
			- Within the applicable sort order, tasks are ordered by priority from `P1` to `P3`.
		- Technical Requirements
			- Extend backend sorting to map priority values explicitly in `P1`, `P2`, `P3` order.
	- Story: Sort tasks by ascending due date
		- Acceptance Criteria
			- Within the applicable sort order, tasks with due dates are ordered from earliest to latest.
		- Technical Requirements
			- Preserve ascending `due_date` ordering after overdue and priority ordering are applied.
	- Story: Place tasks without due dates last
		- Acceptance Criteria
			- Tasks without due dates appear after tasks that have due dates.
		- Technical Requirements
			- Keep undated tasks sorted after dated tasks in the backend task query.
			- Update frontend and backend task tests to cover the revised schema, filters, overdue state, and ordering behavior.
